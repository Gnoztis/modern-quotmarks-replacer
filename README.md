# Modern Quotmarks Replacer

Отключает типографику WordPress (`wptexturize`): кавычки, апострофы, тире,
многоточия, штрихи, знак торговой марки и знак умножения остаются в том виде,
в каком набраны. Никаких «умных» кавычек и длинных тире — ни в контенте, ни в
заголовках, ни в фидах.

Версия 1.1.5. Требуется WordPress 7.0+ (проверено до 7.1) и PHP 8.0+.

## Зачем это нужно

Типографика полезна в художественном тексте, но ломает технический:

- код и команды внутри статьи: `"` превращается в `“`/`”`, и пример перестаёт
  копироваться и подсвечиваться;
- Markdown, JSON, CSV, SQL и регулярные выражения в тексте;
- точный поиск по строке: в базе хранится `"`, а на странице было `“`;
- цитаты и сравнение с оригиналом, где важны исходные символы;
- единообразие: half-width кавычки в исходниках, в выводе и в копипасте.

Плагин ничего не переписывает в базе данных: меняется только вывод.

## Что именно отключается

Отключается не только замена кавычек, а вся типографика целиком. Не
применяются:

- «умные» двойные и одинарные кавычки, апострофы;
- тире (en dash, em dash) и многоточие (`...` → `…`);
- штрихи (prime, double prime) для футов и дюймов;
- знак торговой марки (`(tm)` → `™`) и знак умножения (`9x9` → `9×9`).

По умолчанию типографика выключена везде, где WordPress её применяет: контент
и анонсы записей, заголовки и `<title>`, комментарии, подписи миниатюр,
описания рубрик и меток, заголовки виджетов, название и описание сайта, пункты
меню, списки рубрик, embed-шаблон, фиды, REST API (`content.rendered`) и
админка. Если тема или другой плагин вызовет `wptexturize()` напрямую, текст
тоже останется без изменений.

## Установка

1. Скопировать каталог `modern-quotmarks-replacer` в `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины».

Настроек нет: плагин начинает работать сразу после активации. На уже
опубликованные записи он не влияет — их содержимое в базе не меняется.

## Список хуков и фильтр `mqmr_target_filters`

Дополнительно к глобальному отключению плагин снимает колбэк `wptexturize` с
хуков, на которых его регистрирует ядро (25 регистраций WordPress 7.0 плюс
несколько исторических). Список можно расширить фильтром
`mqmr_target_filters` — например, для собственного поля, которое вы выводите
через `apply_filters()`:

```php
add_filter(
	'mqmr_target_filters',
	static function ( array $filters ): array {
		$filters['my_custom_field'] = 10; // хук => приоритет
		return $filters;
	}
);
```

Приоритет можно указать числом или числовой строкой. Если фильтр вернёт не
массив, используется список по умолчанию.

Фильтр сохранён для совместимости и работает в обоих режимах: в глобальном он
лишь дублирует выключатель и расширяет список, в выборочном — это
единственный механизм отключения (см. следующий раздел).

## Если нужна выборочная типографика

По умолчанию типографика отключена глобально: `wptexturize` не срабатывает ни
на одном хуке и ни при прямом вызове. Если нужно оставить «умные» кавычки на
большей части сайта и убрать их только в отдельных местах, глобальный режим
можно выключить:

```php
// functions.php или mu-plugin
add_filter( 'mqmr_global_wptexturize', '__return_false' );
```

Тогда плагин работает только пер-хуковым списком, как в 1.0.0: `wptexturize`
снимается с хуков из `mqmr_target_filters` (по умолчанию — 29 хуков ядра и
несколько исторических), а на всех остальных хуках типографика остаётся.
Список можно сузить до нужных:

```php
add_filter( 'mqmr_global_wptexturize', '__return_false' );
add_filter(
	'mqmr_target_filters',
	static function (): array {
		return [
			'the_content' => 10,
			'the_title'   => 10,
		];
	}
);
```

В этом примере типографика пропадает только в контенте и заголовках, а в
комментариях, виджетах, фидах и админке остаётся. Решение принимается один раз
за запрос — на первом вызове `wptexturize()`, поэтому фильтр можно спокойно
добавлять из `functions.php`.

## Обновления

Плагин обновляется штатным механизмом WordPress из репозитория
[Gnoztis/modern-quotmarks-replacer](https://github.com/Gnoztis/modern-quotmarks-replacer).
Берётся максимальная версия из GitHub Release и тегов (`v1.1.4` и `1.1.4`
равнозначны); предрелизы (`-beta`) и четырёхчастные версии (`1.1.4.1`) не
принимаются, поэтому достаточно поставить тег. Архив — zip-ассет релиза или
zipball победившего источника; принимаются только `https` и домены GitHub.

Проверка кэшируется на 6 часов (неудачная — на 15 минут); кнопка «Проверить
обновления» в строке плагина сбрасывает кэш и бэкофф, то есть делает реальный
запрос, даже если предыдущая проверка закончилась ошибкой.

### Токен GitHub (необязательно)

Без токена GitHub разрешает **60 запросов в час** на IP-адрес сайта. Если на
одном хостинге несколько плагинов или сайтов проверяют обновления, лимит
исчерпывается: GitHub отвечает `403`, и проверка заканчивается ошибкой — в
админке появляется «проверка не удалась: 403 (лимит GitHub API)». С токеном
лимит — **5000 запросов в час**.

Нужен fine-grained personal access token с правом **Contents: Read** (только
чтение; для публичного репозитория этого достаточно). Токен задаётся в
`wp-config.php`:

```php
define( 'MQMR_GITHUB_TOKEN', 'github_pat_…' );
```

или фильтром `mqmr_github_token`. Без токена плагин работает, но с лимитом
60/ч. Токен передаётся только хостам GitHub: `api.github.com` (запросы к API),
`codeload.github.com` и `objects.githubusercontent.com` (архивы), а на
`github.com` — только для скачивания пакета этого репозитория
(`/releases/download/`); на сторонние хосты и на чужие загрузки он не уходит.

## Переводы

Текстовый домен — `modern-quotmarks-replacer`, шаблон перевода лежит в
`languages/modern-quotmarks-replacer.pot`. Переводимых строк немного: подпись
кнопки «Проверить обновления», описание плагина в окне подробностей и две
диагностические строки для разработчиков.

WordPress 7 подхватывает переводы автоматически; отдельный вызов
`load_plugin_textdomain()` не нужен. Достаточно положить
`modern-quotmarks-replacer-{locale}.mo` (или `.l10n.php`) в
`wp-content/languages/plugins/`.

## Какие данные хранятся

Плагин не создаёт опций, таблиц и метаданных. В базе только два транзиента
кэша проверки обновлений: `mqmr_github_release` (6 часов) и
`mqmr_github_release_error` (15 минут). Оба истекают сами.

При удалении плагина `uninstall.php` удаляет оба транзиента — на всех сайтах
сети, не затрагивая данные других плагинов.
